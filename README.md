# Django Blog — List / Detail и счётчик просмотров

Готовый учебный проект. Python 3.10 или новее; Django 5.2.x; SQLite.
Поле `likes` соответствует названию из задания, но считает GET-запросы (просмотры), а не нажатия кнопки «лайк».

## Быстрый запуск в Windows

1. Распакуйте архив. Откройте папку django_blog_project.
2. Установите Python с добавлением в PATH, если он ещё не установлен.
3. Запустите start_windows.bat. При первом запуске нужен интернет для установки Django.
4. Откройте http://127.0.0.1:8000/blog/ . Остановить сервер: Ctrl+C.

## Ручной запуск

Откройте терминал в папке, где расположен manage.py:

```bash
python -m venv .venv
```

Windows:
```bat
.venv\Scripts\activate
```

macOS / Linux:
```bash
source .venv/bin/activate
```

После активации:
```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_blogs
python manage.py runserver
```

Если в Windows доступна только команда py, используйте `py -m venv .venv` при создании окружения.

## Тесты

```bash
python manage.py test blog -v 2
```

12 тестов проверяют: список и шаблон; объект и ID; контент; пустую базу; ссылку на детальную страницу; данные нужной статьи; неизвестный ID и 404; начальный счётчик 0; увеличение до 1 только у нужной статьи; отсутствие увеличения при открытии списка; два просмотра и значение 2; HEAD без увеличения.
Django создаёт отдельную тестовую базу: тесты не удаляют статьи из вашей рабочей базы.

## Демонстрация TDD — сначала падение, затем успех

Стадия RED использует отдельный URLconf с представлением без счётчика, сохраняя рабочий сайт:

```bash
python manage.py test blog.tests.BlogTests.test_detail_increments_likes --settings=config.settings_red -v 2
```

Ожидается FAIL: 0 != 1. Ненулевой код завершения этой команды является ожидаемым результатом.

Стадия GREEN использует реализованный BlogDetailView:

```bash
python manage.py test blog -v 2
```

Ожидается 12 тестов и OK. Сохранённые результаты фактических запусков находятся в reports/.

## Миграции

В архив включены 0001_initial.py (исходная статья) и 0002_blog_likes.py (новое поле likes с default=0).
Для готового проекта достаточно `python manage.py migrate`.
После собственных изменений модели запускайте:

```bash
python manage.py makemigrations blog
python manage.py migrate
```

## Добавление статей

`seed_blogs` добавляет три примера без сброса существующих счётчиков. Для собственных статей создайте администратора:

```bash
python manage.py createsuperuser
```

Откройте http://127.0.0.1:8000/admin/ .

## Как работает счётчик

`DetailView.get_object()` получает статью или возвращает 404. Для GET выполняется `F("likes") + 1` непосредственно в базе. `refresh_from_db()` возвращает актуальное значение в шаблон. Каждый повторный GET тоже считается. Обновление страницы увеличивает счётчик, список и HEAD — нет.

Проект предназначен для локального учебного запуска: DEBUG=True и демонстрационный SECRET_KEY. Готовой рабочей базы и виртуального окружения в архиве нет: они создаются командами запуска.

## Новое отдельное приложение articles — CRUD

Создано командой `python manage.py startapp articles`. После установки зависимостей и миграций откройте http://127.0.0.1:8000/articles/ . В верхнем меню есть ссылка «CRUD статей».

- Create: /articles/create/ — форма создания.
- Read: /articles/ — список; /articles/<pk>/ — одна статья.
- Update: /articles/<pk>/edit/ — редактирование.
- Delete: /articles/<pk>/delete/ — подтверждение и удаление POST-запросом.

Пустые обязательные поля не сохраняются. Формы защищены CSRF. GET на странице удаления ничего не удаляет. Статьи articles хранятся отдельно от Blog в собственной таблице Article. Авторизация для CRUD не требуется в этой локальной учебной версии.

```bash
python manage.py migrate
python manage.py test blog articles -v 2
```

В текущей версии 26 тестов: 12 blog и 14 articles. Итоговый журнал — reports/all_tests.txt. Старый reports/green.txt относится к исходным 12 тестам блога. Для учебного просмотра создайте первую CRUD-статью кнопкой «Создать статью»; демонстрационные статьи blog остаются в /blog/.
